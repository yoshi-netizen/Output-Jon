## サービス概要

**Output JON** は、自分の考えや感情をうまく言葉にできない人のための、思考の言語化を支援するアプリです。

### 4ステップで、考えを言葉に

1. **テーマ入力**：考えたいことを決める
2. **思考の書き出し**：頭に浮かんだことを箇条書きで書き出す
3. **整理の目的を選択**：【報連相】【学び・感想】【会議・打合せ】【壁打ち】から選ぶ
4. **AIによる要点整理**：目的に合った形にAIが整理し、自分で手直しして保存

続けることで思考が整理され、報告・相談・意見発信がしやすくなることを目指します。

> **サービス名の由来**<br>
> **Output** × **Jo**t dow**n**（さっと書き留める）<br>
> 頭の中の思考を、さっと書き出してアウトプットする。そんな思いを込めています。

## 開発背景

- 工場勤務時代、チーム作業から単独作業へ異動したことで、上司から進捗を確認されることが増えました。
- 報連相を意識しても「何を相談すればいいか」「どう伝えればいいか」が分かりませんでした。
- PREP法などの伝え方を学んでも、根本の **「そもそも自分の考えが整理できていない」** という問題が解決しませんでした。
- あるとき、毎朝A4用紙に思考を書き出す習慣を続けたところ、考えが整理され、報連相や上司とのコミュニケーションが改善しました。
- この経験から、**思考を書き出すこと自体が言語化力を鍛える** のだと気づきました。
- 「この習慣を、もっと気軽に続けられる仕組みがあれば、当時の自分と同じように悩む人の役に立つ」と考え、このサービスを開発しました。

## サービスの利用イメージ

利用例：「学習の進め方」に悩んでいる場合

1. **テーマ** <br>
   学習の進め方

2. **思考の書き出し** <br>
  ・カリキュラムが難しくなってきた<br> 
  ・何を覚えて、何は覚えなくて良いか分からない<br> 
  ・どこまでAIに頼って良いのか<br> 
  ・講師に相談した方が良いと思う<br> 

3. **整理する目的** <br>
【報連相】 どう伝えればいいか整理したい

4. **整理した思考（AI生成）** <br> 
  ■ 結論<br>
  学習の進め方について、優先順位の付け方やAIの活用方法を含めてご相談させてください。<br> 
  ■ 現状・経緯<br>
  カリキュラムの内容が難しくなってきており、学習の進め方に迷いが生じています。<br> 
  ■ 自分の考え・見立て<br> 
  習得すべき情報の選別（何を覚え、何を覚える必要がないか）ができておらず、学習の効率が悪くなっていると感じています。また、学習の過程において、どこまでAIに頼るべきかの境界線が分からず困っています。<br> 
  ■ 相手にお願いしたいこと<br> 
  上記の悩みについて、適切な学習のアドバイスをいただきたいです。お時間をとってご相談させていただけますでしょうか。<br>

## サービスの差別化ポイント

| 既存の方法 | 課題 |
| --- | --- |
| ノート・メモアプリ | 自由度が高すぎて、何を書けばよいか分からない |
| 日記・ジャーナリングアプリ | 時間がかかり、続けにくい |
| AIチャット（ChatGPT など） | 会話が脱線する／AIが意図しない方向に誘導する |
| 人への相談 | 相談する前に、自分の考えがまとまっていない |

Output JONは **「AIに考えてもらう」のではなく「自分の思考を引き出す」** ことを重視しています。

- **何を書けばいいか迷わない**：ステップに沿って箇条書きで書き出すだけ。きれいに書こうとしなくていい
- **短時間で終わる**：書き出したら、目的に合わせて要点を整理するのはAI。自分で一から構成を考える必要がないので続けやすい
- **AIは足さない・誘導しない**：材料は自分が書き出した内容だけ。対話ではなく一度で要点整理するので脱線せず、書かれていないことは補わない。アドバイスや提案もしない
- **相談の前に考えがまとまる**：目的を選ぶと、それに合った構成で要点が整理される。【報連相】なら「結論 → 現状・経緯 → 自分の考え → お願いしたいこと」の、伝える順番に整う

## 技術スタック

| 分類 | 使用技術 |
| --- | --- |
| バックエンド | Ruby 3.4.13 / Ruby on Rails 7.2 |
| フロントエンド | Hotwire（Turbo / Stimulus）/ Tailwind CSS v4 |
| データベース | PostgreSQL |
| 認証 | Devise / OmniAuth（LINEログイン） |
| AI | Gemini API（Net::HTTP で直接リクエスト） |
| 通知 | Action Mailer + Resend / LINE Messaging API |
| テスト | RSpec / FactoryBot / Capybara |
| 静的解析・セキュリティ | RuboCop / Brakeman / bundler-audit |
| CI/CD | GitHub Actions |
| インフラ | Render / Neon |

### 技術選定の理由

**Ruby on Rails：** ユーザー登録・投稿保存・一覧表示といったCRUDが中心のアプリなので、規約に沿って速く安定して開発できる Rails を選びました。

**Hotwire：** 複雑なSPA構成にはせず、JavaScriptの量を抑えながら、AIの結果を画面遷移なしで反映するなどのインタラクティブなUIを実現するためです。

**Gemini API：** 生成の品質とコストのバランスで選びました。

**Resend / LINE Messaging API：** リマインド通知を、ユーザーが普段使っているチャネルに届けるためです。
